# 原生集成、观测与故障经验

## 绑定一次真实执行

冻结候选前记录：DCC/引擎版本、地图与路线、相机、动态对象、渲染 profile、完整源码闭包及相关 Content 的 hash。预览 probe 与 full 必须绑定同一候选；任何影响输出的修复需要新候选和相应 probe，不能沿用失配的旧通过回执。

静态配置、离线测试和原生 build exit0 各有不同含义。build 后由独立的新进程 fresh readback 检查实际保存的对象、组件层级、可见性、变换与引用。日志检查要覆盖完整运行与明确失败模式，不能只看到一句 success。

UE/Blender 等有状态工具要有明确执行所有者，避免两个任务同时改当前地图或启动竞争渲染。保留源资产、旧候选和失败回执；不要为排错执行全局 save-all、覆盖或清理。

## 不用写入替代观测

实际 MRQ 回调应读取实际渲染世界、唯一对应的 sequence/player、真实 clock、对象姿态和整数输出帧。观测器不得强制 set time、驱动 transform、clamp 错误值或跳过首帧，然后把自身写入当作动画成功。

整数输出帧范围与原始浮点 clock 是不同语义：用原生整数输出帧判定输出范围，保留 raw clock，并以事先声明且合理的容差比较。曾出现首帧 clock 是略小于零的浮点误差，虽然输出帧为 0。直接以 `raw_clock >= 0` 作范围门会误拒；但也不能将所有负值截成零来隐藏真正错误。测试需要包含 near-zero、超限、NaN、非唯一 player 和首末帧。

需要姿态证明时，读实际 `FTransform.rotation` 的原始四元数 XYZW；检查 finite、来源、范数和与预期的角距离。Euler 仅作易读元数据。曾有接近 ±90° 时 Euler 转换造成误差显著大于原始四元数误差；应修正观测路径而非放宽姿态门。不得先归一化坏四元数再宣称原始值合格。阈值依精度契约制定，某次使用的 0.02° 不是通用要求。

若首个输出帧的近零负 clock 落在 Transform Section 范围外，原生求值可能回退到地图默认姿态；单纯放宽观测容差不会修复它。按实际子帧／快门契约为 Section 留求值余量，保持输出范围不变，并重验输出 0 的实际对象姿态。另需区分保存地图的初始姿态与剪辑起始姿态：停播恢复应对照前者，用声明过的数值容差核对原始变换，不以浮点字典逐位相等作为物理恢复门。

逐帧位置差分的速度检查需传播位置读回误差：同一位置精度契约下，两帧差分的分量误差上界为 `2 × position_tolerance × fps`，并显式换算单位。大世界坐标的亚毫米量化误差会被差分放大，不能凭任意更小的速度容差判动画失败。保留实际误差记录和严格的位置、原始四元数、clock 门；修改派生检查后重新冻结源码和跑 probe，不沿用旧源码回执。

## 连续微转角不能只做随机 seek

一次 UE 5.8.2 原车序列中，直接 seek 到相邻帧可通过，但从零顺序求值至 149.5 帧时，组件原始世界四元数仍停在起始朝向；RelativeRotation 的 Euler 元数据却持续前进。安装版本的 `MovieSceneTracksCustomAccessors.cpp::SetComponentTransform` 在 `SetRelativeTransform` 后直接写相对位置/旋转，叠加 `SceneComponent.cpp::InternalSetWorldLocationAndRotation` 的微小增量容差，可让每步都很小的转角累积为可见的世界姿态失配。这个结论绑定当时版本源码与只读顺序探针，不是所有 UE 版本的通则。

测试必须覆盖从首帧连续求值、子帧、实际 MRQ 世界中的原始四元数，不能以 RelativeRotation 或随机 seek 代替。该次将三条受影响的道路车辆 yaw 键按 0.001° 精度重新编排，每键最大改动 0.0005°，保留原位置、转弯和完整原车；重新做全部连续整车道路/碰撞检查并独立冻结 probe/full。此精度是该候选的实测修复，不是默认全局参数；仍需验证实际插值、快门子帧及所有正式输出，不通过修改观测器、强制姿态或放宽 0.02° 门来掩盖问题。

复用独立剪辑时，每条已有镜头必须继续用它原来的源码、资产和执行回执核验；新镜头使用新闭包及匹配的 probe/full。不要为了共享代码而改写已成功镜头的冻结文件，也不能把新主镜头的通过回执套到旧开场或交通镜头。

新镜头增加序列包导致历史素材白名单拒绝时，不改历史冻结校验器来放宽未知包。长丰V28的可复用做法是在新剪辑候选先验证当前全部Content字节与新原生结束快照完全一致，再只投影排除精确路径、精确hash且已单独绑定的新序列包，调用原历史校验代码；源码、旧地图和回执不改。未知新增包、旧地图改动、新序列改动均应有拒绝测试。这是核验隔离，不是跳过资产保护。

## 兼容性故障分类

| 症状 | 应验证的对象 | 避免的处理 |
| --- | --- | --- |
| Python 材质枚举缺失 | 实际版本是否暴露、标准导出是否能证明同一属性 | 猜枚举值、跳过材质门 |
| 新组件不是实际 root | 实际根组件、owner 与完整层级 | 仅凭创建函数名称认为挂接成功 |
| GUID wrapper 字符串/等号不等 | API 返回的规范 GUID 值与 fresh binding lookup/owner | 以 wrapper 身份当内容相等 |
| 编辑态动画正常而渲染不动 | MRQ 世界中的实际 player、clock、bound object 与 pose | 只证明编辑态 set time 成功 |
| 首帧失败而中段 probe 通过 | 输出 0、结束边界、warm-up 与子帧 | 只增加中段预览长度 |
| UV 编辑数据正常而 GPU 失真 | 实际 RenderData 精度、材质与小型诊断渲染 | 无证据重做全部源几何 |

这些是问题定位线索，不是跨版本 API 保证。遇到新版本先做最小只读探针，兼容层隔离在新候选中，保留旧成功源；对无法核实的属性应明确失败或阻塞，不伪造通过。

## 原对象恢复与格式兼容

场景整体不可读取、但个别原对象允许提取时，可以先用对象名称与父指针元数据恢复完整后代白名单，再从空场景选择性载入这些对象。集合名可能已经在中间导出中丢失；不能以“没找到集合”推导原层级不存在，也不能只按材质名提取不完整车壳。核对实际载入集合、父级闭包、整车包围盒、材质槽和源文件字节不变。原模型的视觉前向轴不一定是局部 +X，应依据原导出/修正脚本和实际变换确认。

一次 UE 5.8.2 导入中，GLB 的 `EXT_texture_webp` 被明确报为不支持；空导入结果并非异步任务未完成的证据。只有原对象已安全隔离后，才对该白名单文件做格式转换；例如 WebP 解码后存 PNG，比较转换前后 RGBA 字节 hash、几何 accessor/索引字节及材质分配。数据一致不能替代原生材质和人工外观检查。导入回执通过后若退出崩溃，仍需保留失败日志并由独立进程读回，不能把局部成功当整次运行干净成功。

包清单与全部 Content 字节清单的集合不同，后者可能含 `.DS_Store` 等非包文件。先定位缺失与实际改动；对非包文件直接核验字节，分别保持 probe/full 的包集合及全部字节绑定，不靠忽略差异放行。

## 道路与主体构图

原车中心落在路面上，不证明完整车轮廓或帧间转动没有越过中央分隔带。用原对象尺寸核对连续整车 footprint、道路支持高度、车车间距及独立的建筑/树包围盒静态检查。合并物体的粗 AABB 若误覆盖大片道路，只在几何获准时细化为该物体的全部三角形保守边界，不删掉碰撞物或降低安全量。

主体可读尺寸、有限遮挡见证射线与建筑投影占比是独立检查。交通近景不能沿用自制车的固定尺寸或旧镜头焦距；每个实际输出帧绑定实际原车与相机姿态。数值可读性与建筑三角形投影仍不是完整像素中的可见性或人工审美验收。

## 画面缺陷回归

先建立缺陷清单：用户截图/时间码、对应镜头与源帧、对象/材质槽、观察到的现象、待验证原因、修复候选和新输出。截图里的黑区可能来自暗材质、缺面、法线、阴影或深度冲突，不能只凭黑色断言原因。修复后检查实际入剪素材；修改地图不会自动更新复用的旧 MP4。

- **重复表面与光伏闪烁**：在获准的几何范围内确认重叠对象/三角面、法线、深度和材质层。保留需要的可见面层，移除确认多余的副本；不要把必要支撑、屋面或背面一并删掉。近远、掠射角与移动连续帧都要复查，不以静态截图或临时深度偏移证明时序闪烁已消失。
- **地面缺失**：先区分真实孔洞、遮挡/阴影、单面背剔、LOD/流送与错误高度。缺面应补有边界的地面/铺装并正确接壤，检查材质、UV、法线、道路高差和表面重叠；不要用覆盖整个园区的共面大平面掩盖问题，制造新的闪烁或堵住合法空间。
- **车棚过黑**：分别检查顶棚、立柱、充电设施的材质与间接光、天空光、曝光。保留白墙/天空高光的同时让棚下结构可辨，必要时使用合理的局部白色补光，而非全片暴力提曝光或把所有黑色表面改白。灯光、曝光和材质修改后核实渲染世界的实际值与棚下/棚外过渡。
- **指定黑饰面改白混凝土**：用对象和材质槽限定修改范围，注意共享材质可能影响别的建筑。赋予有真实尺度细节、合理粗糙度/法线和非金属响应的白混凝土，保留玻璃、光伏、道路等无关材质；不要只在后期将黑色像素替换成白色。阴影本身不应当作黑材质改色。

新修复先出同机位 probe，再覆盖受影响镜头的正式输出和邻近角度；低清预览可发现问题，不能代替正式质量验收。用户要求重新渲染时记录新任务与新帧来源，不能拿旧帧裁切、放大或变速称为重渲染。只重渲染受影响镜头也需检查剪辑接缝的光照、材质和运动一致性。

片尾鸟瞰的目标是读清项目，不是后退得越远越完整。以用户参考的建筑占比和必要环境为约束，先调整原生相机距离、俯角与焦距，检查透视、全园边界和末段停留；切勿持续后退到建筑不可辨。长丰本轮给出的建筑群横向约 60%–70% 只是该截图的构图目标，不能当其他园区的固定门槛。穿林开头应有明确出口并引向建筑，速度感来自近景视差和有目的的路线，不以长时间拍草地替代主体叙事。

长丰曾多次被指出暗车棚、地面缺失和黑饰面异常。后续候选虽可完成新原生出帧与完整解码，仍不能据此回写历史版本为通过或声称人工接受。原站材质迁入、全场景审计、局部原地面恢复、诊断阴影缓存与新增林带，继续读 [native-scene-repair.md](native-scene-repair.md)；阶段结果以公开案例中的明确日期与验收边界为准。

## 受限画面

若有 NoAI 或类似资产限制，分别核对读取几何、纹理、像素、截图与公开打包的权限。仅在明确获准时做元数据检查。要看去敏诊断，先验证完整受限对象集合、所有 Primitive、每个诊断帧实际隐藏及运行/字节/hash 门，再看允许的输出；不以诊断视图的许可推导完整图像许可。完整画面保留人工正常速度审查。
