# 长丰园区：技术成片与被否决的运镜

本案例公开的是实践中的决策、故障与验收边界，不是原工程的复制或已获认可的效果展示。更新日期：2026-10-20。项目名称仅作案例标识；仅公开脱敏文字和方法，不公开实际路线、资产或内部回执。

## 任务与实际结果

某次候选制作了 43 秒、1920×1080、30fps、1290 输出帧的视频；动态范围是新增 2 辆运动汽车和 4 只飞鸟，不是把所有原有车辆都改成动态。场景当时包含 325 棵树、2382 个植物对象。这里的数量仅交代案例规模，不是技能要求或公开资产清单。

该候选有完整输出帧、实际 MRQ 动态读回、编码和音画完整解码的技术证据。输出采用 `0..1289`，控制键包含 `0..1290` 的边界。技术交付通过不能推出用户接受：用户已经否决旧运镜，最新截图仍呈红紫色，因此不能声称已实现全白、AAA/3A 或视觉验收。

**该阶段的下一道门是确认新航线与视觉方案，而非沿用旧路线再次大规模渲染。**

## 后续：A / C 两个独立运镜候选

用户随后授权 A、C 两案继续制作，并明确本次后续不必逐步确认。A 候选为 51 秒 / 1530 帧，强调速度变化与侧倾；C 为 61.2 秒 / 1836 帧，降低侧倾并单独设计建筑注视，不是将 A 视频简单减速。二者均为 1080p、30fps，包含配乐；原生输出、视频元数据、文件 hash 和完整音视频解码通过。以上只描述技术检查，不构成人工观感认可。

两版实际穿越的是原开敞车棚，不是封闭主楼室内；未合入白光专项，不宣称红紫光已消失或达到 AAA。原方案时长是设计预算，实际因通道与过渡需求延长，效果优先而非硬凑秒数。完整树画面只供人工观看，两个视频、帧序列和其原生资产均未随本仓库公开。

本次还遇到首次编码缺少 BT.709 色彩标签：保留失败证据，用独立合成色块复现并修复帧级色彩元数据后重编码，不改写旧失败状态，也不靠标记成功替代实际验证。候选结果始终保持待人工正常速度视听验收。

## 可复用经验

1. **把运镜评价放到正式渲染之前。** 有路线、车辆、鸟和回望不等于有 FPV 节奏。先确认新的目标、段落、视线和速度，再做正式候选；软件测试不能否定人的视觉反馈。
2. **probe 要覆盖真正危险的边界。** 中段预览成功没发现首输出帧的 raw clock 微小负误差。修复范围判定应使用实际整数输出帧，并保留原始 clock 与容差核验；不 clamp、不跳帧。
3. **姿态应看原始四元数。** 接近 Euler 极点时回读再转换产生误差，实际四元数却正确。修复观测方式，保留严格检查，而不是放松门槛。
4. **版本兼容与原生层级需要实证。** 材质 Python 枚举缺失、Actor root 不匹配、GUID wrapper 比较，都分别用最小探针和 fresh lookup 定位；不能猜 API、绕过材质门或用编辑态结果代替渲染态。
5. **冻结闭包包括地图和 Content。** 修复后生成新候选，probe/full 精确绑定；旧成功构建、失败回执与源资产保留，便于核对与回退。
6. **权限比“可读文件”更细。** 既有树受 NoAI 限制，不能读取其像素、几何或纹理，也不能将其公开打包。完整受限画面由人工验收；允许的去敏诊断必须先通过实际隐藏证明。

## 后续：原车、原站材质与全镜头原生 R5

后续包装曾被否决，不能把早期技术通过写成视觉认可。新的本地候选保留16辆完整原车与4只鸟，使用真实 Source Han Serif SC Heavy900/Regular400、1秒封面硬切、五组章节标题及首尾 `© Nankong`。这些是本案例的明确约束，不是其他项目的默认字体、署名或时长。

R5针对建筑黑面、车棚边缘及道路旁黑带继续做独立原生修复，同时在真实后场草地区补充簇状林带。原325株树不变，仅复用4个获准现有樟树变体追加220株，总计545株。公开案例只记录汇总数量，不发布种植坐标、种子、变换或资产清单。

五段共910帧全新原生输入，10个probe/full任务均退出0。最终本地R5为1920×1080、30fps、922帧、约30.73秒；实际全片音视频解码、15个标题样本及57处源帧连续对应检查通过，15项负向控制与9项最终单元测试通过。180帧原生鸟瞰中的最后45帧相机停稳；旧成片保留，不倒改历史失败状态。这些数量只说明该次验证范围。
